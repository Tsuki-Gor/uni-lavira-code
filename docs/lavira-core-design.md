# LaViRA 共享核心设计

本设计用于把 Habitat、Go1、G1、Cobot 的导航算法提取为可独立调用的 Python 包。四个平台的 VLN、ObjectNav、EQA 都属于第一阶段；先迁移 VLN，再接入另外两类任务。本文是目标契约，完成情况见 [迁移与验收说明](lavira-migration.md)。

原始方案保存在提交 `1c49fc2`，代码行为基线为 `215e7ac`。浏览版见 [统一 LaViRA 方案](../unified-lavira-agent.html)。

## 一次调用的责任边界

外部程序先创建环境、连接传感器和执行器，完成必要的 reset，再把任务和能力交给 LaViRA。LaViRA 在一次调用中维护 TODO、观测历史、LA/VA 推理、回溯和停止判断，发出通用动作，最后返回结果。外部程序接收进度、发出取消请求，并负责关闭或复用环境。

算法包不得导入 Habitat、ROS、Unitree SDK、平台 `config` 或平台入口。平台执行代码不得解析 LA/VA 原始回复，也不得接收 `StrategicDecision` 等算法类型。两侧通过明确的观测与执行数据交接。外部组装文件可以同时导入算法和平台。

导航执行服务负责像素投影、建图、局部规划与控制。现有 FMM、NavDP、iPlanner 保持原实现；它们可以独立于具体硬件复用，无须把所有逻辑塞入驱动。当前仍在本仓库内，只要依赖方向正确，不提前拆成多个仓库或发布多个包。

## 保留行为的含义

固定观测、模型响应和配置后，新入口应发出与原入口相同的模型消息和导航动作，保持关键次序及任务收尾行为。比较包含文本、图像内容与顺序、LA/VA 路由、token 参数、温度、重试、错误回退、方向、bbox 转换、TODO 与停止分支。

允许改变包路径、函数位置、依赖注入和内部数据组织。不借本次重构调整 prompt、默认移动、安全距离、停止阈值、模型选择或相机采样策略。日志路径的整理不得改变送入模型的历史图内容。

共享循环通过已有差异的有限兼容配置执行。不能在四个 profile 中各放一个完整 `run()`，也不能只把原有循环移到四个新目录就宣称统一。保留两个请求实现以兼容 Habitat 与机器人协议，不等于保留两套导航 pipeline。

## 最小代码组织

| 位置 | 职责 |
| --- | --- |
| `lavira/` | 共享算法包；根模块不导入重依赖 |
| `lavira/clients.py` | 先承接完全相同的机器人客户端；配置显式传入 |
| `lavira/runtime.py` | 任务、进度、结果、取消状态和运行时契约；使用标准库 |
| `lavira/agent.py` | 唯一高层任务驱动，组织决策、执行、记忆更新和收尾 |
| `lavira/reasoning/` | 已有 prompt、消息构建、解析和兼容策略；按实际差异组织 |
| 现有平台目录 | 环境生命周期、观测、投影、控制、评测和组装入口 |
| `tests/` | 不依赖机器人或模型服务的行为对照与边界检查 |

模块在迁移到相应职责时再创建，不提前铺空文件。Python 语法兼容 Habitat 使用的 3.8；保留各平台现有依赖版本约束。继续使用已有 OpenAI SDK、NumPy、Pillow 等能力，不引入新的 RPC、插件框架或测试框架。

## 数据与调用契约

接口首先服务已有四个平台。下列语义必须落实到实际类型和方法中；低层相机字段不强行统一成一种硬件结构。

| 数据 | 必须承载的含义 |
| --- | --- |
| 任务 | 类型为 VLN、ObjectNav 或 EQA，指令/目标/问题，已有步数或循环预算 |
| 观测 | 图像及其通道约定、尺寸、有效方向；需要投影时同时保存深度、单位、相机参数、采集位姿和参考系 |
| 像素目标 | 绑定观测引用与像素坐标；归一化输出先按原规则解析，执行端不再猜测模型格式 |
| 位置目标 | 数值、单位和参考系；不能把地图格与米制坐标混用 |
| 执行反馈 | 是否发出/返回、是否有到达证据、超时或失败信息，以及执行后可用的观测 |
| 进度 | 所处阶段、任务计数与必要摘要；不把模型内部推理当成对外协议 |
| 结果 | 结束原因、答案（EQA）、任务计数、执行证据；环境成功指标由外部提供或评估 |

观测作为一次采集的快照使用。历史视角的 RGB、深度、相机参数和位姿必须配套保存，尤其是 Habitat 回溯。核心不暗中读取机器人对象上的最新图像。对于旧执行器内部重新取实时深度的行为，兼容层明确记录这一例外并保留；改成历史帧绑定执行须单独决定。

运行时提供获取观测、转向、像素/位置导航及任务结束动作。命名和返回字段可以随实际抽取收敛，但不能提供“执行 LA 决策”“确认 LaViRA 停止”这种算法专用方法。停止确认是模型推理，留在核心。

完整任务调用接收任务、运行时、可选进度回调和取消信号。每次调用建立独立算法状态；运行时的连接和设备由外部管理。第一阶段不增加远程调用或服务守护进程。

## 不同平台的兼容策略

| 行为 | Habitat | Go1 | G1 | Cobot |
| --- | --- | --- | --- | --- |
| 视角 | 四方向，采集需 12 次仿真动作 | 三方向 | 四方向 | 七个有效方向，含斜向 |
| 初始 TODO | 任务对应结构化生成 | 使用占位文本 | 独立 LA 请求 | 空 TODO |
| VA | RGB 与深度 | RGB；进度及地标 | RGB；方向与理由 | RGB；地标及进度 |
| 深度锚点 | 一般底边，楼梯按旧执行规则 | bbox 高度约 75% 处 | 底边中心 | 底边中心或图像中心回退 |
| 记忆 | 全景、连续帧、历史位姿、重访关系 | iPlanner 历史图 | iPlanner 历史图 | 文字目标历史 |
| 回溯 | 历史观测重规划或直接返回 | 无同等分支 | 无同等分支 | 无同等分支 |
| 停止 | 最后接近、二次确认、三次失败强制停止 | 有 bbox 则最后接近 | 有 bbox 则最后接近 | LA STOP 直接结束；TODO 完成也结束 |
| 到达信息 | 现有地图阈值、环境反馈 | 轨迹执行返回不证明到达 | 轨迹执行返回不证明到达 | 动态导航返回布尔值 |

Habitat 可视化使用的楼梯锚点和执行使用的锚点存在差异，不能仅看可视化代码推导执行。Go1/G1 的轨迹安全距离是从路径末端留出缓冲，不是把行进距离限制为该常数。三端问答收尾的相机选择、消息与调用时机分别保留。

## 生命周期、取消与失败

取消信号可在线程间发出，在任务现有检查点生效。不得把“已接收取消请求”写成“机器人已停止”。模型调用和局部控制中的阻塞、退出等待以及取消后的 EQA 收尾均属于现有行为，增强这些行为需要单独的决定和提交。

环境自然结束、预算耗尽、模型停止、异常和请求取消应能区分。兼容策略可以保留原有的默认目标与解析回退，但对外结果不能因此虚构成功。Go1/G1 原执行方法返回 `None`，只能记录返回事实；Cobot 的 `True` 可以记录旧控制器报告到达，仍不等于独立物理验证。

新核心不增加对物理动作的自动重试，也不把异常恢复解释为可以重放一次移动。原有模型重试和控制器内部重规划则照旧保留。

## 待用户决定的行为问题

这些是独立的问题清单，不构成本阶段的修复授权。

1. JSON 解析失败或 bbox 缺失时仍可能默认移动。改为停止会影响容错行为和导航表现。
2. G1/Cobot 用坐标是否小于等于 1000 推断归一化；小图像上的像素框也可能再次缩放。需要明确未来坐标格式。
3. Go1/G1 的轨迹执行缺少可信到达返回；把命令返回当到达会误导任务结果。
4. 取消检查不覆盖全部模型请求、导航阻塞和问答收尾；控制入口等待旧任务退出也可能不足。
5. 部分执行器使用实时深度、缺失定位时使用默认位姿，可能与模型选定图像不同步。
6. Habitat 客户端的 `get_model_info()` 读取未定义的旧属性；当前调用链未使用它，本次抽取保留原状。

若要修复，先列出触发条件、现状、建议变化和测试，再取得用户决定；修复提交与抽取提交分开。
