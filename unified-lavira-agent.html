统一、独立的 Lavira Agent 循环

第一期只覆盖室内地面：HabitatSim 与三台真机（Unitree Go1、Unitree G1、Agilex Cobot Magic）。 把四套重复的 LA → 转向 → VA bbox → 规划执行收成一个无仿真/真机依赖的 lavira/ 包。 空中仿真与无人机真机这一版先不纳入。

1. 问题与目标

当前仓库没有共享包。Habitat 评测和每台地面真机都各自复制了一套 Lavira Agent 循环。 哲学相同——语言决策（LA）→ 转向对向 → 视觉落地（VA bbox）→ 本体执行——但全景采集、坐标系和规划器绑在各自目录里。

要独立出去的

  • LA / VA HTTP 客户端
  • Prompt 组装与 JSON 解析
  • TODO / 历史图 / visited waypoint 记忆
  • 宏观状态机（唯一 Loop）

必须留在本体的

  • Habitat 建图、FMM、SPL/NDTW
  • iPlanner / ROS / Unitree SDK
  • 云台扫全景、Web UI
  • 各端评测与部署入口
形态已定：独立 Python 包，进程内 import，不做 RPC Agent 服务。 第一期接口按 Habitat + 三台地面真机设计；切流按 Habitat → Go1 → G1 → Cobot。
这一版明确不覆盖 AirSim / TravelUAV 和自研无人机。它们的 VA 输出（距离/高度）和 3D 航点执行与地面室内循环差异过大，后续单独再挂。

4. 统一循环：详细代码逻辑

这是重构后 Habitat 与三台地面真机共用的宏观状态机。本体差异全部沉到 adapter.*。 四端都走同一条 Indoor 路径：LA 出离散方向，VA 出 bbox，adapter 把 bbox 投到坐标再执行。

LaviraAgentLoop.run_episode — 统一宏观循环
flowchart TD
    Start[run_episode instruction] --> Reset["adapter.reset episode"]
    Reset --> InitMem[memory.clear TODO history waypoints]
    InitMem --> MaybeTodo{profile.need_init_todo?}
    MaybeTodo -->|yes| GenTodo["brain.generate_todo panorama0 instruction"]
    GenTodo --> LoopHead
    MaybeTodo -->|no 由首次 LA 生成| LoopHead[while not done]

    LoopHead --> Pan["panorama = adapter.capture_panorama"]
    Pan --> RecWP["memory.record_waypoint pose panorama"]
    RecWP --> LA["la = brain.language_action instruction panorama memory"]
    LA --> ParseLA{"la.mode"}

    ParseLA -->|stop| Confirm{"adapter.confirm_stop la"}
    Confirm -->|confirmed| StopAct["adapter.stop"]
    Confirm -->|rejected| Feedback["memory.stop_feedback += rejected"]
    Feedback --> FailCnt{"consecutive_stop_failures >= 3?"}
    FailCnt -->|yes| StopAct
    FailCnt -->|no| LoopHead
    StopAct --> EQA{"task == EQA?"}
    EQA -->|yes| Oracle["brain.query_oracle panorama instruction"]
    EQA -->|no| Done[return EpisodeResult]
    Oracle --> Done

    ParseLA -->|backtrack| BTGoal["goal = adapter.backtrack_goal waypoint_id"]
    BTGoal --> ExecBT["result = adapter.execute goal"]
    ExecBT --> MemBT["memory.update la result"]
    MemBT --> LoopHead

    ParseLA -->|navigate| Face["adapter.face la.direction"]
    Face --> TacView["view = adapter.capture_tactical_view"]
    TacView --> VA["va = brain.vision_action view la instruction"]
    VA --> ParseVA{"va.kind"}

    ParseVA -->|stop 且无 bbox| StopAct
    ParseVA -->|bbox| Ground["goal = adapter.ground va view"]
    Ground --> Exec["result = adapter.execute goal"]
    Exec --> MemUp["memory.update la va result"]
    MemUp --> Timeout{"result.timeout or reached?"}
    Timeout --> LoopHead

5. EmbodimentAdapter 协议

本体唯一需要实现的缝。Loop 不调用 Habitat / ROS / Unitree SDK 的任何 API。

class EmbodimentAdapter(Protocol):
    def reset(self, episode) -> Observation: ...
    def capture_panorama(self) -> List[TaggedView]: ...
    def face(self, direction) -> None: ...
    def capture_tactical_view(self) -> RGBDFrame: ...
    def ground(self, va: TacticalDecision, view: RGBDFrame) -> Goal: ...
    def execute(self, goal: Goal) -> StepResult: ...
    def stop(self) -> None: ...
    def confirm_stop(self, la: StrategicDecision) -> bool: ...  # 可选，默认 True
    def backtrack_goal(self, waypoint_id: int) -> Goal: ...     # 可选
方法HabitatSimGo1 / G1Cobot Magic
capture_panorama 12× TURN_LEFT，抽 4 向 多相机一次拍齐 双臂云台扫 8 槽
face 排队 3/6 次 30° 转 rotate 90° / 180° 8 向转角（45°×N）
ground get_world_xz_from_pixel → 地图格 深度反投影 → 机体系 (x, y) 深度反投影 → 导航像素 / 机体系
execute FMM/NavDP 直到到达或 15 步超时，期间持续建图 iPlanner HTTP，截断 SAFE_DISTANCE 后跟轨迹 进程内 iPlanner + 连续 cmd_vel
confirm_stop 再扫全景 + double_check_stop 有 bbox 则做最终接近，无 bbox 立即停 同地面真机，按任务实现

ZeroShotVlnEvaluatorMP.rollout — 四阶段导航周期
flowchart TD
    Init["_maps_initialization: reset env, instruction, Semantic_Mapping"] --> While["while step < max_step"]
    While --> Analyze["ANALYZE: save RGB/depth, update pose, history_images"]
    Analyze --> DoneQ{dones?}
    DoneQ -->|yes| Metric["_calculate_metric SPL NDTW"]
    DoneQ -->|no| EmptyQ{action_list empty?}

    EmptyQ -->|no| Act["ACT: envs.step action_id"]
    Act --> MapUp["mapping_module + collision_map"]
    MapUp --> While

    EmptyQ -->|yes| Timeout{"same target steps >= 15?"}

    Reset1 --> Step1
    Timeout -->|no| Reach{"dist to target < 0.75m?"}

    Reset2 --> Step1
    Reach -->|no| Branch{state}

    Branch -->|"target is None and going_to_stop"| StopChk
    Branch -->|"target is None and not navigate_or_not"| Step1
    Branch -->|"panorama done, no queued turns"| Step2
    Branch -->|"have target_map_xy"| Step3

    StopChk["get_panorama 12 turns"] --> DCS["agent.double_check_stop"]
    DCS -->|confirm| Stop0["action_list.append STOP=0"]
    DCS -->|reject less than 3| FB["stop_feedback, re-enter Step1"]
    DCS -->|reject >= 3| Stop0
    Stop0 --> EQA2{EQA?}
    EQA2 -->|yes| Oracle2["query_llm_oracle"]
    FB --> While

    Step1["STEP1 get_panorama 12 turns"] --> Rec["append visited_targets waypoint"]
    Rec --> LAH["agent.navigate_or_backtrack"]
    LAH --> LAAct{decision.action}

    LAAct -->|STOP| FlagStop["going_to_stop=True"]
    FlagStop --> While
    LAAct -->|BACKTRACK| BT{"backtrack_second_chance?"}
    BT -->|yes| Replan["replan_at_backtrack + VA bbox at old waypoint"]
    BT -->|no| BTOnly["target = old waypoint world_coords"]
    Replan --> Step3
    BTOnly --> Step3
    LAAct -->|NAVIGATE| QueueTurn["queue 3 or 6 TURN_LEFT/RIGHT"]
    QueueTurn --> NavFlag["navigate_or_not=True, panorama_got=True"]
    NavFlag --> While

    Step2["STEP2 agent.query_llm VA"] --> BBox["parse bbox_2d 0-1000"]
    BBox --> Unproj["get_world_xz_from_pixel -> target_map_x y"]
    Unproj --> Step3

    Step3["STEP3 FusionMapPolicy._get_action or NavDP"] --> Push["push MOVE_FORWARD / TURN into action_list"]
    Push --> While

9. 抽什么 / 不抽什么

抽进 lavira/

  • 双模型客户端，沿用 LA_* / VA_*
  • Prompt 注册表：以 Habitat vlnce_baselines/prompts/ 为底本
  • TODO / 历史图 / visited waypoint
  • JSON 解析与重试
  • 宏观 Loop

故意不抽

  • 建图、分割、FMM、NavDP、iPlanner
  • 数据集、episode loader、指标
  • ROS / Unitree SDK / 云台 / Web
  • 各端 conda / Docker 环境
  • 第一期不改 prompt 语义和评测协议
  • AirSim 与无人机真机（后续再挂）

10. 迁移顺序

接口按地面室内四端设计，切流分四步，避免评测漂移
flowchart LR
    P1["1. extract lavira package + shared client"] --> P2["2. Habitat Loop + HabitatAdapter"]
    P2 --> P3["3. Go1 Adapter"]
    P3 --> P4["4. G1 then Cobot"]
  1. 共享 client：Habitat / Go1 / G1 / Cobot 旧 LaViRA_API / LaViRAVisionClient 先换成同一实现，循环先不动。
  2. Habitat 先接 Loop：以 VLMReasoningAgent + rollout 为底本，验证 Indoor 最完整路径（backtrack、STOP 二次确认、EQA、楼梯）。
  3. Go1：最接近 Habitat 的真机线性循环，adapter 主要实现全景、转向、bbox 反投影和 iPlanner 执行。
  4. G1 → Cobot：同一 Indoor 循环的变体，差在视角数、STOP 字段和执行器。
每接一端的验收：原有评测/部署入口还能跑；Habitat 指标不因抽包而漂。 先抽包、不改策略，避免把重构和调参混在一起。

明确不做

  • 不合并各平台 conda / Docker
  • 不把建图或规划器做成统一导航栈
  • 第一期不改 LA/VA 模型、prompt 语义或评测协议
  • 第一期不接入 AirSim 与无人机真机
